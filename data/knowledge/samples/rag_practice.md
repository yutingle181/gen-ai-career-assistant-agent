# RAG 工程实践要点

## 1. 文档解析

企业知识库的文档来源通常包括 PDF、Word、Markdown、HTML 和数据库导出文本。
PDF 解析是难点：扫描件需要先做 OCR，文本型 PDF 可能出现文字层错乱、表格串行、
页眉页脚混入正文等问题。常用工具是 pypdf 与 pdfplumber，前者速度快，
后者对表格支持更好。

## 2. 数据清洗

清洗的目标是把噪声降到最低，常见规则包括：
去除页眉页脚与孤立页码、剔除目录行（以连续点号结尾并跟页码）、
合并重复行、删除控制字符与乱码符号、压缩连续空行。
清洗后应统计丢弃比例，如果丢弃超过 30% 需要检查解析环节是否有问题。

## 3. 文本切分

切分策略直接决定召回质量。固定长度切分实现简单但容易切断语义，
推荐用递归字符切分：优先按段落、再按句子、最后按字符切。
中文场景 chunk_size 通常取 300 到 600 字，overlap 取 10% 到 20%。
过小的片段语义不完整，过大的片段会引入无关信息并增加 token 成本。

## 4. Embedding

中文场景常用 bge-m3、bge-large-zh、text-embedding-v3。
选择时应关注三点：向量维度、最大输入长度、是否支持多语言。
生产环境通常用云端 API 以换取稳定性，
对数据合规要求高的场景才考虑本地部署 sentence-transformers。

## 5. 向量库与检索

小规模（十万片段以内）用 FAISS 即可，索引类型 IndexFlatIP 配合归一化向量
等价于余弦相似度，召回精度最高且无需训练。
大规模再考虑 HNSW 或 IVF-PQ。

## 6. 混合检索

单纯向量检索对专有名词、型号、岗位名等关键词不敏感，
工业界普遍采用 BM25 与向量的混合检索。
融合算法首选 RRF（Reciprocal Rank Fusion），
公式为 score(d) = Σ 1 / (k + rank_i(d))，k 一般取 60，
无需归一化分值也无需调权重。

## 7. 重排

召回阶段追求高召回率，重排阶段追求高准确率。
常用 cross-encoder 类模型（如 bge-reranker-v2-m3）对 top-N 候选重新打分。
没有 GPU 时可用大模型打分作为替代方案，成本更高但零部署成本。

## 8. 效果评测

核心指标包括 Recall@K（正确片段是否进入前 K）、MRR（正确片段排名倒数的均值）、
Hit Rate 与幻觉率。幻觉率通常用 LLM-as-judge：
把回答拆成若干断言，逐条判断是否可由召回片段支撑。
评测必须做 A-B 对比，例如「有无重排」「向量 vs 混合检索」。

## 9. 成本与稳定性优化

常见手段：相同 query 结果缓存、流式输出降低感知延迟、
指数退避重试应对限流、按 token 统计成本并设置预算告警、
对输出做内容安全过滤。
